## [4.0.0] — 2026-11-09 — claude-5-modernization (MAJOR: the pipeline keeps every gate and sheds its instruction weight; Claude 5 sessions get the task tools back; seven new capabilities land behind pointers, not paragraphs)

The proposal `docs/proposals/CT6_MODERNIZATION_PLAN.html` (measured against v3.67.0 on 2026-11-08) drove this release end to end. Two field facts anchored it: a Claude 5 session ships without `TaskCreate`/`TaskUpdate` unless `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` is set, so the Phase 3 evidence gate and the completion lock were silent on exactly the models the plugin now runs on; and the Lead read roughly 141K tokens of its own rule surfaces before Phase −2 started, 13× the 5,000-token budget Claude Code keeps per skill after a compaction. Both are closed here, measured.

## [3.67.0] — 2026-08-29 — git-commit-identity (MINOR: a run commits as the PERSON driving it, and the tool never decides who)

The defect (user report 2026-08-29 — *"Paul Ingram is me but others use this tool"*): `skills/mini-architect-team-pipeline` carried one maintainer's hardcoded `git -c user.name=… -c user.email=…` author override in its M7 commit step, so every mini run on every user's machine committed as that maintainer; the main pipeline's Phase 8 alternative was "the repo's local git config", which on a fresh clone is nothing and on a shared machine is someone else. Neither is a decision the tool may make for the user. Built solo, red-first, in one pass.

- **NEW substrate `hooks/git_identity.py`** (NOT a wired hook — the `deploy_config.py` shape; importable by the gate, runnable as a CLI). The record is `<main-worktree>/.architect-team/git-identity.json` — `{name, email, source, recorded_at}` — resolved through `git rev-parse --git-common-dir` so every run worktree of a checkout shares it, gitignored with the rest of `.architect-team/` (identity is per PERSON, never committed into the repo). Verbs: `resolve` (recorded → candidate from the repo's LOCAL git config → candidate from the GLOBAL config → missing; exits 0 with the status in its output so the polyglot `||` form is safe), `set` (validates — refuses a blank name, a newline, an email without `@` / with whitespace or angle brackets, an unknown source; atomic write), `status`, `args`, and the **`git -- <args>` wrapper** that injects `-c user.name= -c user.email=` from the record and REFUSES (exit 2) when there is none. Git config is read only to PROPOSE a candidate and is never written. Console output ASCII-only (cp1252-safe).
- **The front door asks, once.** The six lane commands (`/architect-team`, `bug-fix`, `mini`, `data-eng`, `ux-test`, `playwright-suite`) gain `## Commit identity (v3.67.0)` immediately after the dispatch banner, before any step can touch git: `recorded` → one line, no question; `candidate` → CONFIRMED via `AskUserQuestion` (never adopted silently — the first checkout this ran on offered a typo'd `user.name`); `missing` → the user is ASKED for name + email. A **domain gate** (the v0.9.21 carve-out): fires regardless of `--proposal-first`, once per checkout, records `source` as its evidence trail, never guesses, never reuses a name found in a skill / a CLAUDE.md / another repo, never writes the user's git config.
- **Every commit carries the record.** `architect-team-pipeline` Phase 8 step 5, `bug-fix-pipeline` B8, `mini-architect-team-pipeline` M7 (the hardcoded override REMOVED), `data-eng-pipeline` D8, `ux-test-builder` U9 and the `playwright-suite` command's P9 step now author through the wrapper or the explicit `-c` pair; `scripts/setup/worktree_lifecycle.py::merge_branch_to_main_and_prune` reads the same record (`_commit_identity_args`) so the auto-merge commit is authored as that person too.
- **Enforced — `hooks/pretool_skill_gate.py` Arm 4** (`_git_identity_check`, kill-switch `CT6_GIT_IDENTITY_GATE_DISABLED`): during an ACTIVE, non-stale run, a Bash command whose git subcommand authors a commit (`commit` / `merge` / `revert`; `--abort` / `--no-commit` / `--dry-run` author nothing) is refused when the checkout has no record, when it carries no `-c user.name= / -c user.email=` pair (the wrapper counts as carrying it), or when it carries a DIFFERENT identity — with the exact wrapper command in the block. Same deliberate shape as Arm 3: payload-only (no transcript dependence), scoped to the run marker so a plain session's own git usage is never hijacked, `escalation-pending.md` does not stand it down, its own kill-switch is the human's lever.
- **Canonical rule** `common-pipeline-conventions` `## Git commit identity discipline (v3.67.0)` in the house pointer shape (heading + STOP pointer + one paragraph; 257358 → 258527 LF bytes, still under the 259290 cap, ledger appended) + NEW `references/git-commit-identity.md` (record schema, resolution order, the `AskUserQuestion` shapes, enforcement, changing the identity — *"commit as Jane Doe from now on"* → `set --source user-stated` — and the rationalization table). This repo's own `CLAUDE.md` / `README.md` convention lines switch from the named override to the wrapper.
- **NEW `tests/test_git_identity.py`** — real git fixtures with `GIT_CONFIG_GLOBAL` pointed at a temp file (the developer's real global config is never read or written): the resolution order, the record's refusals, the cross-worktree share, the command inspection matrix (14 authoring / non-authoring shapes; quoted and `-cuser.name=` joined forms), the CLI round trip, the wrapper refusing without a record and committing as the recorded person with one, the merge helper's author, the full Arm-4 matrix (no run / no record / carried / wrapper / bare / mismatch / merge / stale / escalation-pending / kill-switch / other tools), the six front-door pins, the lane commit-step pins, and a **maintainer-identity sweep** over `skills/ commands/ agents/ hooks/ scripts/` so no shipped surface can name a committer again.

HONEST BOUNDARY: the arm proves a record EXISTS and that every commit CARRIES it; it cannot prove the user was asked before the record was written — `source` plus the visible front-door question are the evidence trail, and a `source: asked` record on a transcript with no question is the tell a reviewer looks for. Counts UNCHANGED (skills 56 / agents 39 / commands 26 / hook scripts 7 / Layer-3 tools 24; `git_identity.py` is a substrate, not a wired hook). ## [3.65.0] — 2026-08-26 — playwright-suite-intuition-lifecycle (MINOR: the intuition map becomes a guaranteed, growing, debugging-fed asset, and the Playwright suite becomes a durable, persona-grouped, dev/prod-split artifact)

Three verified gaps drove this (user requirement 2026-08-25, brief at `docs/proposals/PLAYWRIGHT_SUITE_AND_INTUITION_LIFECYCLE.md`): `INTERACTION_INTUITION_MAP.md` existed only when a pipeline's Phase −1D produced it and `playwright-user-flows` never read it; nothing grew the map from user-specified flows or debugging discoveries; and no durable suite registry existed — no inventory, no whole-suite enumeration at full integration, no dev/prod safety split.
