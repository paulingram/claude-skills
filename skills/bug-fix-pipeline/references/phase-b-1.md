# Phase B−1 — Intake & Mapping (REQUIRED, runs before Phase B0)

Follow the `intake-and-mapping` skill verbatim — same codebase discovery (read `$REQ_DIR/codebases.json` → frontmatter → cwd → ask user); same per-codebase `ct6-converge` workflow with cartographer + route-mapper + the tier-3 reviewer convergence (the `codebase-map` and `integration-map` presets, declared before and recorded after); same map-freshness rules (read `last_mapped` and compare against `git log -1 --format=%cI`; re-derive if stale or if `map_invalidated`); same integration mapping; same MemPalace wake-up + mining.

**The freshness pre-scan is non-negotiable.** A bug fix proposed against a stale map is the second-worst class of bug fix (after one proposed without replication). If the maps are current per the freshness rules, Phase B−1 short-circuits cleanly and the loop moves to B0 quickly.

Per the v0.9.21 Phase −1D step in `intake-and-mapping`: if any frontend codebase is in scope and a low-confidence interaction-intuition union exists at the end of Phase −1, the bulk-verify gate fires before B0. This is a domain gate; it applies here too.

**Map convergence declares and records (v4.0.0).** The per-codebase map review and the integration synthesis this phase reuses are **review tier 3** gates (map convergence, per `skills/team-spawning-and-review-gates/references/review-tiers.md`) run as the `ct6-converge` workflow — the `codebase-map` preset (`reviewers: 3`, promise `CODEBASE MAP COMPLETE`) and the `integration-map` preset (`reviewers: 3`, promise `INTEGRATION MAP COMPLETE`) — each DECLARED before the workflow runs and RECORDED after it per `skills/architect-team-pipeline/references/phase--1.md` `### Converge record protocol (v4.0.0)`. The exit condition is the recorded all-`ok` round; the promise string is only the gate's label. When `cartographer` is absent (a CONDITIONAL plugin since v4.0.0) the map is produced in the native form per `skills/common-pipeline-conventions/references/native-methodology.md` and still converges the same way.

**Front-door bindings go to the decisions ledger (v4.0.0, best-effort, never blocking).** The `appearance_mode` binding made at the top of B−1 (`## Appearance-change policy (v3.14.0)`) is appended the moment it is made: `python3 "${CLAUDE_PLUGIN_ROOT}/hooks/decisions_ledger.py" add --workspace "<workspace>" --kind appearance --summary "appearance_mode bound to <mode>" --chosen "<mode>" --rejected "<other mode>=<why: flag / prose signal / strict-by-nature default>" || python "${CLAUDE_PLUGIN_ROOT}/hooks/decisions_ledger.py" add --workspace "<workspace>" --kind appearance --summary "appearance_mode bound to <mode>" --chosen "<mode>" --rejected "<other mode>=<why: flag / prose signal / strict-by-nature default>"`.
