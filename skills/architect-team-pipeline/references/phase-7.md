# Phase 7 — Master Review

Once all task groups report complete:

1. Walk every commit produced during the build. For each, attribute it to one or more requirements via the coverage map.
2. Re-run `openspec validate --all --strict --json`.
3. Walk the coverage map and confirm every requirement now has:
   - Implementation (commit reference)
   - Passing unit/integration tests
   - Passing Playwright flows where applicable
   - A demonstrable artifact (curl example, trace, screenshot)
   - For every entity-bearing feature: the `editability-completeness` convergence reached `satisfied` at the Phase 7 count — **review tier 3** (`skills/team-spawning-and-review-gates/references/review-tiers.md`), run as the `ct6-converge` workflow with the `editability` preset (`kind: "editability"`, `promise: "EDITABILITY COMPLETE"`, `reviewerAgent: "architect-team:editability-reviewer"`, the owning teammate as fixer, `reviewers: 3`) over the feature's converged map, declared before and recorded after (`skills/common-pipeline-conventions/references/converge-workflows.md`); `satisfied` means the record shows all three reviewers `ok` with zero gaps in the same round. An unsatisfied editability loop is a coverage gap — the Lead re-runs the workflow after the fix lands (it re-creates the editability-reviewer tasks in teams mode, or re-dispatches the editability-reviewer subagents in subagents mode).
   - For every frontend feature with interactive surface: the `interaction-completeness` convergence reached `satisfied` at the Phase 7 count — **review tier 3**, the `ct6-converge` `interaction` preset (`kind: "interaction"`, `promise: "INTERACTION COMPLETE"`, `reviewerAgent: "architect-team:interaction-reviewer"`, the owning frontend teammate as fixer, `reviewers: 3`), declared and recorded the same way; `satisfied` is the recorded all-`ok` round with zero gaps. An unsatisfied interaction loop is a coverage gap — the Lead re-runs the workflow after the fix lands (it re-creates the interaction-reviewer tasks in teams mode, or re-dispatches the interaction-reviewer subagents in subagents mode).
4. If any gap exists, the Lead re-dispatches the appropriate teams (re-enter Phase 2) to close it — creating new tasks in the shared list (teams mode) or dispatching fresh subagents (subagents mode). This meta-loop continues until the coverage map is fully green.
5. **Independent master review — review tier 3 (`skills/team-spawning-and-review-gates/references/review-tiers.md`): three independent reviewers + one synthesis.** The orchestrator's own coverage-map walk (steps 1–4) is a producer-is-own-checker step: the orchestrator ran the build, then the orchestrator audited it. So after the orchestrator's walk, the Lead runs the `ct6-converge` workflow with the `master-review` preset — `kind: "master-review"`, `promise: "MASTER REVIEW COMPLETE"`, `reviewerAgent: "architect-team:task-reviewer"`, `reviewers: 3`, `artifacts: [the coverage map, the SR directory, the commit ledger, the review-evidence directory]`, with a `fixerPrompt` that says the Lead re-enters Phase 2 for every deficiency — declared before and recorded after (`skills/common-pipeline-conventions/references/converge-workflows.md`). Then, as the synthesis seat, the Lead creates a `system-architect` task in Master Review Audit mode (teams mode) OR dispatches the `system-architect` subagent in that mode (subagents mode), passing the coverage-map path, the SR directory, the commit ledger, the review-evidence directory and the converge record. The agent INDEPENDENTLY re-verifies every coverage-map entry (commit + passing tests + demo artifact) and every SR (`resolved`, with a diagnostic plan where required), re-runs `openspec validate`, and writes a verdict JSON to `<cwd>/.architect-team/master-review/audit-<ISO-8601-UTC>.json` with `overall` (`pass` / `fail`) and per-entry findings. The audit verdict must be `overall: pass` to proceed — if it is `fail`, treat each finding as a gap, re-enter step 4 (the Lead re-dispatches the appropriate team), and re-run the audit. Phase 7 is not complete until the independent audit returns `overall: pass`. **Deterministic enforcement (v3.9.2):** the `pipeline-completion-audit` hook ALSO re-runs `openspec validate --all --strict` itself at this gate (`_audit_openspec_validation`, fired whenever a master-review verdict exists) — so the master-review gate does not rely on the agent's self-reported `openspec_validate` field; any invalid active change (stale / orphaned / malformed) blocks the Phase 8 commit until it is fixed or archived.
6. Once all requirements are satisfied AND the master-review audit verdict is `overall: pass`, apply `superpowers:verification-before-completion` (evidence before assertions — run the verification commands and confirm output before claiming completion, per `## Plugin prerequisites (v3.9.0)`), then run `openspec archive <change-name>` to merge deltas into the canonical specs.
