# CLAUDE TEAM SIX (CT6)

> Internal plugin slug: `architect-team` (preserved for backward compatibility with existing installations + the 30 slash commands). CLAUDE TEAM SIX is the user-facing display name introduced in v2.2.0.

## What this repo is

This repo IS the source of the **CLAUDE TEAM SIX** Claude Code plugin (internal slug `architect-team`) — a spec-to-production multi-agent coding pipeline. It orchestrates **MemPalace wake-up → Phase −2 (Triage) → Phase −1 → 8** against a requirements folder or a plain-language requirement, with sibling pipelines for **bug-fix** (`/architect-team:bug-fix`), **UX testing** (`/architect-team:ux-test`), **mini** (`/architect-team:mini`), **data-engineering** (`/architect-team:data-eng`), and **Playwright-suite building** (`/architect-team:playwright-suite`, v3.65.0).

Current shape (v4.1.0): **60 skills, 39 named agents, 30 slash commands, 9 hook enforcement scripts (10 wired events), 26 Layer-3 verification tools** (counts disk-anchored; `check_separation` 26). The suite count for the current release is the CHANGELOG's top entry, **RECORDED, not asserted**: `docs/measurements/` carries the frozen-tree bracket, and a release run cannot end its turn with an unbacked count. Python is 3.10+ **stdlib-only** throughout; green under both Windows cp1252 and `PYTHONUTF8=1`.

**v4.0.0 (the Claude 5 modernization) changed where the rules live, not what they are.** The constitution is `skills/common-pipeline-conventions/SKILL.md` (ranked rules + stubs); every discipline's full text is a chapter under `references/` and `references/INDEX.md` says what to Read before each phase (the lane skills carry their own `references/INDEX.md`). Agents preload `skills/ct6-agent-core` instead of carrying compiled blocks; models follow roles (`set_default_model.py --split role`); reviewer counts follow `team-spawning-and-review-gates/references/review-tiers.md`; `workflows/ct6-converge.js` runs every reviewer-convergence loop; `superpowers` / `cartographer` are conditional with `references/native-methodology.md` as the fallback; `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` is written by setup because Claude 5 ships without the task tools the gates read. New in v4.0.0: the deletion guard (`hooks/deletion_guard.py`), project principles (`scripts/principles/`, `/architect-team:principles`), the test index + selector (`scripts/test_index/`), sample-first data iteration (`scripts/data_dictionary/sampling.py`), page publishing (`scripts/publish/`, `/architect-team:publish`), the project homepage + timing log + decisions ledger (`scripts/homepage/`, `hooks/timings_log.py`, `hooks/decisions_ledger.py`, `/architect-team:home`), and the instruction-budget measurement (`scripts/measure/instruction_budget.py`). Tests read the SURFACE an agent receives (`tests/helpers/surfaces.py`), never the raw file.

## Conventions at a glance

- Commit as this checkout's RECORDED identity, never ambient git config (the machine's git config carries a typo'd `user.name`, which is exactly the case the v3.67.0 discipline exists for): `python hooks/git_identity.py git -- commit ...` (the wrapper injects `-c user.name= -c user.email=` from `.architect-team/git-identity.json`), or the explicit pair from `python hooks/git_identity.py status --json`. The record is created once per checkout — a CT6 run asks at the front door; by hand it is `python hooks/git_identity.py set --name "<name>" --email "<email>" --source user-stated`. No shipped surface names a committer (`tests/test_git_identity.py` sweeps for it).
- Read before you act (v4.0.0): the constitution's `## Read this first` is the only always-loaded rule text; before each phase open the relevant `references/INDEX.md` and Read the chapters it lists. Tests pin the SURFACE (`tests/helpers/surfaces.py`), so moving text into a chapter never breaks a pin; a dead pointer does (`scripts/compliance/instruction_compliance.py`).
- Run the selected tests while building (`python scripts/test_index/cli.py select --workspace . --phase 3 --baseline <sha>`); the whole suite runs once before a merge.
- Run the test suite via `python -m pytest -v` from repo root (green under both Windows cp1252 and `PYTHONUTF8=1`; the expected pass/skip count for the current release is in the CHANGELOG entry).
- Bump version: update `.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json` + `CHANGELOG.md`.
- **Release order is a constraint, not a preference (v3.60.0; sharpened v3.61.0).** Reconcile version + CHANGELOG **first**, **archive the OpenSpec change second** (the `git mv` changes the tree, so archiving after measuring stales the artifact — measured, v3.61.0), commit until the tree is clean, **then** `python scripts/measure/suite_measurement.py --label v<version>` as the LAST act, then commit the artifact (committing it is invisible to the digest by design). Measuring earlier records a `provisional` artifact that backs nothing. Close with `python scripts/docs_tooling/changelog_check.py --require-measurements` — exit 0 or the release is not backed. **This repo has no CI and no pre-commit hook, so that command is the ONLY place the existence arm bites; it is checklist-strength, not gate-strength, and it is on the releaser to run it.**
- Runtime state lives under `.architect-team/` (gitignored). v1.1.0 splits it into **shared** (in main worktree: `locks/`, `run-history/`) and **per-run** (in current worktree: `reviews/`, `teammates/`, `handoffs/`, this-run's `openspec/changes/<slug>/`); the MemPalace itself lives at the workspace root `.mempalace/palace`, NOT under `.architect-team/`. The `scripts/setup/worktree_paths.py` helper resolves both via `shared_state_dir()` / `run_state_dir()`. **v1.2.0** auto-creates the run worktree (default; `--no-worktree` opts out) via `scripts/setup/worktree_lifecycle.py::create_run_worktree(slug)` — branch `architect-team/<slug>`, path `<parent-of-repo>/<repo-name>-<slug>/`. **v1.3.0** auto-cleans merged worktrees on the next run via `cleanup_merged_worktrees()` (with `exclude_current=True` keeping the cwd safe); the `/architect-team:cleanup-worktrees` command is the on-demand variant. **v3.7.0** auto-merges a clean run's branch `--no-ff` into `main` and prunes it (`--no-auto-merge` opts out; a conflict falls back to a PR, never `--force`).
